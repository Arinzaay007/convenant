## Option A: GitHub + Vercel

1. COVENANT is linked to Vercel at <https://convenant-omega.vercel.app/> from the public repository `https://github.com/Arinzaay007/convenant`. The early root-server deployments built but returned `500 FUNCTION_INVOCATION_FAILED`; **do not use them for keys or wallet actions**. A subsequent revision uses explicit `api/*.mjs` Vercel Functions plus static `public/` rather than Vercel's root HTTP-server autodetection. Open your own Vercel dashboard to confirm the latest GitHub commit deployed and check runtime logs if any endpoint still fails. Do not share your account tokens in chat.
2. The `vercel.json` file forces the **Other** framework and static `public/` output and applies CSP to those files. The actual API logic lives in `covenant-server.mjs`, reached through fixed-route wrappers under `api/`; local Node/Docker hosting starts from `main.mjs`. On Vercel, the in-memory request limiter is **best effort per function instance**, not a global abuse defense; browser repeat protection is scoped to this HTTPS origin.
3. Open the production `https://…vercel.app` URL in a **top-level browser tab** and verify, without a wallet prompt: `/api/health` returns `ok: true`; `/`, `/app.js`, `/pilot.js`, `/style.css` load; `/api/check` with missing figures fails closed; live `/api/vaults` and `/api/weather` work. If Vercel gives 404/500, protection/login redirects, missing JS/CSS, or blocked external reads, **stop and share the public URL or error**. Never sign from an unverified deployment.

1. **Do not share a GitHub access token in chat.** Download `covenant-github-upload.zip`, extract it **on your own device**, create a new public GitHub repository, then use **Add file → Upload files** to drag the extracted files and folders into its **root** (not the ZIP itself). The root should contain `Dockerfile`, `main.mjs`, `covenant-server.mjs`, `api/`, `vercel.json`, `render.yaml` and `public/`, not an extra enclosing folder. Commit the upload. `covenant-submission.zip` instead contains an outer `covenant/` folder. Never commit secrets, `.env` files or the private wallet-preflight report.
2. In your own Render account, create a **Blueprint** from that GitHub repo. The included `render.yaml` builds the `Dockerfile`, runs the Node site on port 3000 and checks `/api/health`.
